# ⚖️ Praetor: Indian Law Q&A with cited answers

Praetor answers questions about Indian central legislation and cites the exact section or article behind every claim. It uses hybrid retrieval (BM25 + dense embeddings, fused with reciprocal rank fusion), a cross-encoder reranker and an evidence gate that refuses rather than guesses. Answers are generated by **Qwen** through any OpenAI-compatible endpoint.

It also understands the 2024 criminal-law transition. Questions asked in old-code terms ("IPC 420", "CrPC 125") are mapped to the current BNS / BNSS / BSA provisions, and both are shown.

## How it works

```
question ─► detect section refs (IPC 302, Art. 21…) ─► old→new code mapping (IPC→BNS, CrPC→BNSS, IEA→BSA)
         ─► BM25 (bm25s)  ┐
         ─► dense (BGE-small, cosine) ┼─► RRF fusion (top 30) ─► cross-encoder rerank (MiniLM) ─► top k
         ─► exact section lookup ┘
         ─► evidence gate (best rerank score < τ → refuse)
         ─► Qwen with numbered sources, citation-only answering ─► citation check ─► answer + source cards
```

| Component | Choice |
|---|---|
| Corpus | 28 core central Acts (Constitution, BNS/BNSS/BSA, IPC/CrPC/Evidence Act, CPC, Contract, NI, IT, RTI, HMA, POCSO, …) from **Open India Law** at section level |
| Chunking | One chunk per section/article, long sections split into 320-word windows with a 60-word overlap; each chunk carries Act, section, title, status and source URL |
| Lexical | BM25 (`bm25s`) |
| Dense | `BAAI/bge-small-en-v1.5` via `fastembed` (ONNX, CPU, no torch) |
| Reranker | `Xenova/ms-marco-MiniLM-L-6-v2` cross-encoder |
| LLM | Qwen (default `qwen/qwen3-32b` on Groq) through an OpenAI-compatible API; also works with local Ollama |
| UI | Streamlit |

## Retrieval evaluation

`eval/questions.jsonl` holds 36 questions with gold (Act, section) labels. `scripts/eval_retrieval.py` reports Recall@k and MRR for each retrieval mode, and the GitHub Action writes the latest numbers to [`eval/results.md`](eval/results.md).

## Run locally

```bash
pip install -r requirements.txt
python scripts/build_index.py          # downloads ~26 MB parquet, builds index/ (a few minutes on CPU)
export LLM_API_KEY=...                  # Groq key; or see "LLM options"
streamlit run app.py
```

Without an API key the app still runs in sources-only mode.

### LLM options

| Provider | `LLM_BASE_URL` | `LLM_MODEL` |
|---|---|---|
| Groq (default) | `https://api.groq.com/openai/v1` | `qwen/qwen3-32b` |
| Hugging Face router | `https://router.huggingface.co/v1` | `Qwen/Qwen2.5-7B-Instruct` |
| Ollama (local) | `http://localhost:11434/v1` | `qwen2.5:7b` |

## Deploy (Streamlit Community Cloud)

1. Run the **Build index** GitHub Action once (Actions tab → Build index → Run workflow). It commits `index/` and `eval/results.md`.
2. On share.streamlit.io choose **Create app**, pick this repo, set the main file to `app.py` and Python to 3.12.
3. Under **Advanced settings → Secrets**, add:
   ```toml
   LLM_API_KEY = "gsk_..."
   ```

If `index/` is missing, the app builds it on first start instead (slower cold start).
